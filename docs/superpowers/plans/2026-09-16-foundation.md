# Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the current single Next.js app with a pnpm monorepo (`apps/web` Vite+React SPA, `apps/api` FastAPI service) wired together end-to-end through a trivial health-check vertical slice, with lint/test/CI in place, so every later phase (real SQL parsing, auth, new UI) has a working skeleton to build on.

**Architecture:** `apps/web` (FSD-structured Vite SPA) calls `apps/api` (FastAPI, DDD bounded contexts `schema_design` and `identity`) over `/api/*`. Contracts flow one way: `apps/api` is the source of truth, `packages/api-client` generates TS types from its OpenAPI schema so `apps/web` never hand-writes the contract. `packages/ui` holds shared React components. No feature logic yet — this plan proves the wiring, not the product.

**Tech Stack:** pnpm workspaces, Vite, React 19, TypeScript, Tailwind CSS v4, Biome, ESLint (react-hooks + jsx-a11y only), Vitest + React Testing Library, FastAPI, SQLAlchemy 2.0 + Alembic, Neon Postgres, Ruff, pytest, GitHub Actions, Vercel.

**Spec:** [docs/superpowers/specs/2026-09-16-foundation-design.md](../specs/2026-09-16-foundation-design.md)

## Global Constraints

- Package/workspace manager: **pnpm workspaces** (whole repo, TS side).
- TS lint + format: **Biome** repo-wide; **ESLint** only for `eslint-plugin-react-hooks` + `eslint-plugin-jsx-a11y` (no overlapping rules).
- TS tests: **Vitest + React Testing Library**.
- Python web framework: **FastAPI**. ORM/migrations: **SQLAlchemy 2.0 + Alembic**. Lint+format: **Ruff**. Tests: **pytest**.
- Database: **Postgres via Neon** (production + a separate dev branch). No local Postgres, no Docker.
- Deploy target: **Vercel** (`apps/web` static build, `apps/api` as a Python function via `vercel.ts` rewrites).
- **Docker is removed entirely** in this plan: `Dockerfile`, `Dockerfile.dev`, `docker-compose.yml`, `docker/`, `.dockerignore`, and any `Makefile` targets that invoke them.
- No bare `except: pass` or silent error swallowing — every later phase inherits this; Foundation's own error handling (health check) must follow it too.
- Each bounded context in `apps/api` keeps `domain/` free of FastAPI/SQLAlchemy imports.

```python
from enum import Enum


class InvalidDialectError(ValueError):
    def __init__(self, value: str):
        super().__init__(f"Unknown SQL dialect: {value!r}")


class SqlDialect(str, Enum):
    POSTGRES = "postgres"
    MYSQL = "mysql"
    SQLITE = "sqlite"
    MSSQL = "mssql"

    @classmethod
    def from_string(cls, value: str) -> "SqlDialect":
        normalized = value.strip().lower()
        for member in cls:
            if member.value == normalized:
                return member
        raise InvalidDialectError(value)
```
